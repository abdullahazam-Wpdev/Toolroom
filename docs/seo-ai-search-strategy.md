# Technical SEO and AI-search strategy

Primary authority: https://developers.google.com/search/docs/appearance/ai-features. The page was opened on 25 October 2026. AI-search eligibility rests on crawlable, useful content and ordinary SEO practices; do not promise inclusion, citations or rankings. Claude SEO skills are references, not search-engine authority.

Keep original task instructions in initial server-rendered HTML, unique metadata and self-canonicals, semantic headings, descriptive links, accurate SoftwareApplication/BreadcrumbList schema and a generated sitemap. Publish only tested functionality as available. Exclude unavailable tool pages from the sitemap and mark them noindex. Avoid identical filler descriptions and fabricated reviews.

Audit reports must separate observed HTML, network checks, lab measurements and field data. Use null/Not tested for missing measurements. Robots directives are not proof of indexing. Multiple H1s are a review signal, not an automatic ranking penalty. Schema JSON parsing is basic validation, not Google Rich Results certification.

Provide concise definitions, limitations, evidence and source references so both people and retrieval systems can understand the work. Optional llms.txt is documentation discovery, not a ranking factor or guaranteed AI access mechanism. Do not import unsupported GEO statistics, spam recommendations or bot-specific hidden content.

Track future improvement through actual Search Console and consent-reviewed analytics. Do not claim a 90+ Lighthouse score or field Core Web Vitals without measurements. Field data may be absent and PSI is deprecating embedded CrUX data; support separate CrUX configuration later.

## PageSpeed quota diagnosis — 25 October 2026, resolved same session

The recurring quota error was expected, not a bug: without `PAGESPEED_API_KEY`, `queryPageSpeed` (`apps/web/src/lib/pagespeed.ts`) calls `pagespeedonline/v5/runPagespeed` with no `key` parameter, sharing Google's very low unauthenticated per-IP quota, which this environment's egress already exhausted. The operator supplied a real Google API key later the same session; it was set in `apps/web/.env.local` and verified live against `/api/pagespeed` for both mobile and desktop, returning real Lighthouse lab scores and real Chrome UX Report field percentiles for `https://example.com`. `pagespeed-checker` stays `requires-configuration` in the registry (every other deployment still needs its own key) but is fully functional on this running instance. Full detail in `docs/progress.md`.

## Pexels and Semrush credential activation — 25 October 2026

The operator supplied real Pexels and Semrush credentials. **Pexels verified live**: a real search and a real downloaded/decoded photo both succeeded through the actual production routes, no code changes needed. **Semrush did not activate**: the supplied token (`semrtkn-pat-...`) does not match either documented v4 credential type (an API key sent as `Authorization: Apikey <key>`, or a legacy OAuth2 token sent as `Authorization: Bearer <token>`) per Semrush's own authorization docs, and a single real test call returned HTTP 403 (not billed — auth failures aren't). It is very likely a Personal Access Token from Semrush's App Center developer portal rather than an account API key. `semrush-keyword-metrics` remains `requires-configuration`; the fix is to generate an actual API key from the account's API Keys page, not the App Center PAT. Full detail in `docs/progress.md`.
